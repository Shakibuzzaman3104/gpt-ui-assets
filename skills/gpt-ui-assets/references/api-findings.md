# Probe findings (2026-09-27)

Measured against a 1024×1536 meditation-app mockup generated by gpt-image-2. The calls went through an
OpenAI-compatible gateway backed by ChatGPT subscriptions ([sub2api](https://github.com/Wei-Shaw/sub2api)).
The official OpenAI API may honour parameters this backend ignores (see below). The kit works either way.

## Endpoints

| Endpoint | Works | Notes |
|---|---|---|
| `POST /v1/images/generations` | yes | text→image, 35–55 s |
| `POST /v1/images/edits` (multipart `image`) | yes | one reference image, 35–65 s; `input_fidelity=high` accepted |
| `POST /v1/images/edits` with `image[]` ×2 | **no** | returned the mockup itself (a faded full screenshot), which is the copy failure |
| `POST /v1/responses` + `image_generation` tool | yes | gpt-6 rewrites the prompt (`revised_prompt`), 75 s, fidelity similar to an edit |
| `POST /v1/responses` vision + `json_schema` strict | yes | asset inventory with tight bboxes in 77 s; the full design spec takes ~3 min |
| `GET /v1/models` | yes | gpt-6, gpt-6-sol/luna/astra, gpt-5.6(-sol/-terra/-luna), gpt-5.5, gpt-5.4(-mini), gpt-image-1, -1.5, -2, -2.5-flare, -2.5-sunburst |

Large base64 payloads must go in a request body file, never a shell argument (ARG_MAX gives an empty body).

## Parameters that backend ignored

- `quality: high` comes back as `medium` (icons) or `low` (large opaque edits). It can't be forced.
- `size` isn't honoured: 1024² → 1254², 1536×1024 → 1774×887, and edits sometimes follow the reference's aspect ratio instead.
- The output aspect follows the prompt's wording more than `size`. "stats screen" came back square despite
  1024x1536, so `mockup` states the aspect in the prompt and retries once on a mismatch.
- `n: 2` returns 1 image.
- `background: transparent` **is** honoured on every image model, with real alpha.

## Fidelity experiments (campfire icon, 96×120 px in the design)

| Method | diff ↓ | Notes |
|---|---|---|
| text-only prompt (4 models) | — | generic, different style; never do this for approved designs |
| edit, full mockup as the reference | 21.8 | right style, colours drift yellow |
| **edit, focused crop (60% margin, 4× upscale) as the reference** | **13.8** | closest; now the `forge` default |
| full-mockup edit + vision-diff corrective edit | 25.9 | over-corrected, which is why `fix` only keeps improvements |
| forge run (crop ref, 2 candidates) | 12.5 / 14.4 | best-of-2 helps |

These are recreations, not extractions. The generated content is 5–7× the design's resolution and its edges are
40–100× sharper than the upscaled crop, with new detail. A copy would score close to 0 on diff against its reference.

## Copy / crop detection (score())

- `COPY:returned-mockup`: output ≈ full mockup at 64×64 (mean diff < 10).
- `COPY:returned-reference`: output ≈ reference crop at 64×64 (mean diff < 8).
- `OPAQUE`: less than 15% fully transparent pixels on an asset that should be transparent.
- `BACKDROP`: more than 30% of solid pixels are close to the design's backdrop colour (the circle or card behind the icon was kept).
- `CUT-OFF`: content touches the canvas edge.
- Sharpness ratio alone is not a copy signal: smooth gradient art scores ~6 while still being a clean redraw.

## SVG

gpt-6 vision writes clean, correct SVG for tab-bar/toolbar/gear/chevron/play/equalizer glyphs, in one call per
6 assets with the crops attached. It picks colours from the context, for example dark glyphs on a lavender button.
It uses Q/H/V commands and userSpaceOnUse gradients, which VectorDrawable supports.

## Animation

- Whole-object sprite sheet: static parts drift between frames and it drew grid lines despite "no grid lines".
- **Moving-layer-only sheet** ("only the flame, no logs, empty transparent space between cells"): clean, no dividers, consistent style.
- The static layer comes from an edit of the approved asset ("keep only the logs, same canvas"). Pad the asset to
  a square first, then register it back to the asset by a scale/offset search. The moving frames get placed by a
  silhouette search against the asset.
- Vector keyframes: gpt-6 returns morph-compatible paths (identical M/C/Z sequences) when asked for absolute M/L/C/Z only.
  The motion is subtle by default and there's no glow layer.

## Timing and cost

Each image call takes 35–80 s. Vision/text calls take 40–110 s, and the full design spec about 3 min. Eight concurrent image calls
run fine. On a ChatGPT-subscription gateway, about 15 image calls used roughly 10% of one account's 5-hour window.
On the official API, budget per image call at the provider's image pricing.
